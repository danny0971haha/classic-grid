# Artifacts

`historical/classic-v0.2-checkpoint-e-results.non-authoritative.json` is the rejected Checkpoint E campaign file. Its `E-01`..`E-30` `result="PASS"` values were synthesized before the Node test process ran. It is kept only as a historical record and is **not** machine evidence.

Authoritative Checkpoint E evidence is the GitHub Actions artifact `classic-v0.2-checkpoint-e-results` generated by `tools/checkpoint-e-evidence.ts` with schema `classic-v0.2-checkpoint-e/3`:

```text
npm run evidence:checkpoint-e
npm run evidence:checkpoint-e:verify
```

The generator runs two real suites:

- `checkpointSuite`: TAP from `test/experiment-v02-checkpoint-e.test.ts` (E-01..E-30)
- `projectSuite`: TAP from the same file list as `npm test`, plus the non-TAP `test/grid.test.ts` pre-check exit code

It does not copy the 30-case Checkpoint E TAP into `projectSuite`. It does not fill PASS from `CASE_IDS`. `fullSuite` is not a field in schema v3. Do not check in a generated results JSON that claims the current commit SHA.

On `push`, `identity.sourceHeadSha` and `identity.testedCheckoutSha` may be the same commit. On `pull_request`, `sourceHeadSha` is the PR head and `testedCheckoutSha` is the GitHub merge checkout; those SHAs must not be stored as one field.
